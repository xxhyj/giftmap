# PRD — Giftmap

이 문서는 현재 저장소에 구현된 로컬 MVP를 기준으로 작성했다.
현재 단계 범위 밖(외부 AI/API/서버/실제 상품·제휴)은 "제외" 절에 따로 정리한다.

## 1. 문제 정의

- 선물을 사야 하는 순간은 대개 갑자기 오고, 이동 중 짧은 시간 안에 결정해야 한다.
- 일반 쇼핑 검색은 "무엇을 살지 이미 아는 사람"에게 최적화되어 있다.
- 선물 결정에는 관계, 연령, 상황, 예산, 취향, 금기 조건이 동시에 작용한다.
- 상품을 너무 일찍 나열하면 선택 피로와 광고 불신이 커진다.

GiftMap은 "어떤 방향으로 찾을지"를 좁혀 주고, 그 방향에 맞는 **실제 상품 후보까지** 보여준다.
사용자는 조건을 고른 뒤 상품을 둘러보고, 비교하고, 찜해 두고, 상세를 확인할 수 있다.

## 2. 타깃 사용자

1. 이동 중 급하게 선물을 골라야 하는 20–40대 모바일 사용자
2. 상대 취향을 잘 모르는 직장 동료·지인 관계
3. 예산은 정했지만 품목을 정하지 못한 사용자
4. 선물 금기와 관계 예절을 걱정하는 사용자

## 3. 핵심 가치

> 사진이나 긴 설문 없이, 몇 번의 탭 또는 한 줄 검색으로
> 실패 가능성이 낮은 선물 후보를 상품 단위로 보여준다.

- 로그인이 필요 없다.
- 네트워크가 없어도 추천이 끝까지 동작한다(모든 계산이 기기 안에서 이뤄진다).
- 추천 이유와 주의할 점을 함께 제시해 결정을 설명 가능하게 만든다.

## 4. 핵심 사용자 시나리오

**시나리오 A — 선택형 위저드**

1. 홈에서 "선물 찾기 시작하기"를 누른다.
2. 상황 → 관계/연령 → 예산 → 실용↔감성 → 피하고 싶은 것 순으로 5단계를 고른다.
3. 분석 화면을 지나 조건에 맞는 상품 목록을 2열 그리드로 받는다.
4. 상품을 열어 추천 이유·참고사항을 확인하고 마음에 들면 찜한다.

**시나리오 B — 상품 검색**

1. 홈에서 검색으로 들어가 "디퓨저"처럼 원하는 것을 직접 찾는다.
2. 카테고리·가격대 필터와 정렬로 결과를 좁힌다.
3. 상품 상세로 이동해 확인하고 찜한다.

**시나리오 C — 자연어 조건 입력**

1. 홈 검색 대신 자연어 조건을 입력하면 로컬 파서가 조건을 뽑는다.
2. 조건 확인 화면에서 파서가 못 읽은 항목만 직접 고른다.
3. 분석 → 상품 추천 결과로 이어진다.

**시나리오 D — 기록 재사용**

1. 기록 탭에서 지난 추천을 연다.
2. "이 조건으로 다시 추천"을 눌러 같은 조건을 현재 규칙으로 다시 계산한다.

**시나리오 E — 기념일**

1. 홈에서 기념일 목록을 열고 이름·관계·종류·날짜를 등록한다.
2. D-day가 가까운 항목에서 "선물 추천받기"로 위저드에 진입한다.

## 5. MVP 범위 (현재 구현됨)

- 상품 중심 홈 큐레이션(인기·가격대별·관계별·상황별·할인·최근 본 상품)
- 로컬 상품 검색: 키워드·카테고리·가격대 필터·정렬·빈 상태
- 선택형 위저드 5단계와 자연어 조건 확인 진입
- 결정론적 로컬 추천 엔진(카테고리 방향 + 상품 점수화)과 상품 추천 결과
- 상품 상세: 이미지, 가격/할인, 설명, 추천 이유, 참고사항, 비슷한 상품
- 찜하기(앱 전체 일관 동작, 재실행 후 유지)
- 최근 본 상품(자동 기록, 중복 제거, 최신순, 최대 50개, 재실행 후 유지)
- 카테고리 탭: 상위 그룹 → 세부 카테고리 → 정렬 → 반응형 상품 그리드
- 찜 탭: 저장한 상품 모아보기
- 기록 탭: 최근 본 상품 / 추천 기록 (검색 키워드는 저장하지 않는다)
- 추천 기록 목록·상세·삭제·재사용
- 기념일 등록/조회/삭제와 추천 연결
- 설정: 앱 정보, 분석 동의(기본 꺼짐), 개인정보 안내, 제휴·광고 고지, 오픈소스 라이선스, 문의, 데이터 전체 삭제

Bottom Navigation은 **홈 / 카테고리 / 선물추천 / 찜 / 기록** 5탭이다.
검색은 탭이 아니라 홈 최상단 검색창으로 들어간다.
`Search`, `Analyzing`, `Result`, `Product Detail`, `History Detail`, `Anniversary`, `Settings`는
탭이 아니라 흐름 위에 push로 열린다. 선물 찾기 5단계는 선물 찾기 탭 안에서 전환된다.

## 7. 사용자 입력 구조 (`GiftIntent`)

| 필드 | 값 | 필수 |
|---|---|---|
| situation | 생일·기념일·승진·감사·집들이·출산·명절·응원·기타 | 필수 |
| relationship | 연인·친구·가족·직장 동료·상사·지인 | 필수 |
| ageBand | 10대·20대·30대·40대+·선택 안 함 | 선택 |
| budget | 1만원 이하 / 1~3 / 3~5 / 5~10 / 10만원 이상 / 직접 입력 | 필수 |
| customBudget | 1,000원 ~ 10,000,000원 정수 | 직접 입력일 때 |
| preference | 0.0 실용적 ~ 1.0 감성적 | 기본 0.5 |
| avoidTags | 향·식품·사이즈·취향 강함 | 선택 |
| rawQuery | 자연어 원문 (화면 표시용, 저장·전송하지 않음) | 선택 |

성별은 입력받지 않으며 고정관념을 점수에 반영하지 않는다.

## 8. 추천 결과 구조

내부적으로 카테고리 방향 3개(`RecommendationResult`)를 먼저 정하고,
그 방향을 보너스로 반영해 **상품 목록(`ProductPick`)** 을 만든다. 사용자에게는 상품이 보인다.

`Product`의 주요 필드:

| 필드 | 설명 |
|---|---|
| id / brandName / productName | 식별자, 브랜드, 상품명 |
| category / categoryLabel / subCategory | 분류 |
| price / originalPrice / discountRate | 판매가와 할인 정보(정가가 낮으면 할인 없음 처리) |
| imageAsset | 로컬 asset 경로. 없으면 카테고리 비주얼을 그린다 |
| tags / occasions / recipientTypes / ageRange / priceRange | 추천 매칭용 속성 |
| description / recommendationReason | 상품 설명과 기본 추천 이유 |
| isDemo | 항상 true. 화면에 데모 배지와 고지를 표시한다 |

`ProductPick`은 상품에 더해 `score`(0~100), `riskLevel`, 카드용 `badge`,
상세용 `reason`을 담는다.

가격은 실시간 시세가 아니며 화면마다 데모 데이터 고지가 함께 노출된다.
값이 없는 가격을 0원으로 표시하지 않는다.

결과 화면에서는 조건 요약, 추천 이유 문장, 조건 수정, "추천 상품 더 보기"를 제공한다.

## 9. 찜과 최근 본 상품

- 찜은 상품 카드와 상세에서 같은 방식으로 동작하고, 중복 저장되지 않는다.
- 최근 본 상품은 상세 진입 시 자동으로 기록되며, 같은 상품은 앞으로 이동하고 최대 50개를 보관한다.
- 둘 다 기기 로컬에 저장되어 앱을 다시 켜도 유지된다.
- 찜은 독립 탭, 최근 본 상품과 추천 기록은 기록 탭의 두 세그먼트로 나뉜다.
- 검색 키워드 기록(Search History)은 저장하지 않는다.

## 10. History

- 추천이 끝나면 생성일·`GiftIntent`·추천 3개가 기록으로 남는다.
- 목록은 상황 라벨로 필터링할 수 있고, 홈에는 최근 3건이 노출된다.
- 상세에서 당시 추천을 다시 열람하고, 같은 조건으로 재추천하거나 삭제할 수 있다.
- 삭제는 확인 다이얼로그를 거친다.
- 현재 저장은 **인메모리**다. 앱을 다시 켜면 비워진다(영속화는 이후 단계).

## 11. Anniversary

- 이름·관계·기념일 종류·날짜를 등록하고 D-day 기준으로 정렬해 보여준다.
- 확인 다이얼로그 후 삭제할 수 있다.
- 항목에서 바로 선물 추천 흐름으로 연결된다.
- 기기 밖으로 전송하지 않으며, Push Notification은 구현하지 않는다.

## 12. Settings & Legal

- 앱 정보와 현재 추천 규칙 버전, 안전 기본값으로 동작 중인지 여부
- 익명 사용 통계 동의 (기본 false, 동의 전에는 아무것도 기록하지 않음)
- 개인정보 안내: 기록·기념일은 기기에만 저장, 로그인 없음, 광고 식별자·연락처와 결합하지 않음
- 제휴/광고 고지, Demo 가격 고지
- 오픈소스 라이선스(Flutter 기본 라이선스 화면), 문의 안내
- 로컬 데이터 전체 삭제 (확인 다이얼로그 후 기록·기념일·분석 이벤트 삭제)

## 13. 현재 단계에서 제외되는 기능

- 외부 AI / LLM 기반 의도 파싱·문구 생성
- 서버·DB·REST/GraphQL·네트워크 요청 일체
- 실제 상품 데이터, 실시간 가격·재고, 실제 제휴 링크와 클릭 정산, 외부 상품 이미지
  (상품 상세의 "상품 보러가기"는 데모 상태로 **비활성화**되어 있고 이유를 화면에 설명한다)
- 로그인·결제·장바구니·배송·판매자 기능
- Push Notification, 카메라, 관리자 CMS
- 추천 기록·기념일의 영구 저장(현재 인메모리. 찜·최근 본 상품만 로컬에 저장된다)

## 14. 향후 확장 가능한 기능

1. 동일한 `RecommendationRepository` 계약을 구현하는 원격 추천 연결
2. 서버 기반 자연어 의도 파싱과 응답 스키마 검증
3. 실제 상품 카탈로그와 출처·관측일을 가진 시세 데이터로 교체
4. 제휴 딥링크와 고지·클릭 측정
5. 추천 기록·기념일 로컬 영속화와 마이그레이션
6. 기념일 알림 권한과 스케줄링
